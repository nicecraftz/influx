Scope: everything under `src/influx/`, `pyproject.toml`, `docker-compose.yml`, `README.md`, `.env.example`, plus the uncommitted working tree (9 modified, 6 untracked files).
Method: full read of every source file, `uv run python -c "import influx.main"`, `ruff check --select E,F,B,I,UP,ASYNC,S`.

Each item is written so it can be pasted as an issue: **title**, priority, where, what is wrong, what to do.

- **P1** — must be done before anything is reachable from the internet.

- **P3** — hygiene, tooling, docs. Do when convenient.

## 0. Headline

1. **The API does not import.** `uv run python -c "import influx.main"` raises `RuntimeError: Passing nullable is not supported when also passing a sa_column` from `User.hashed_password`. Every command (`init-db`, `crawl`, `embed`) imports the models, so the CLI is broken too.
2. **Nothing is authenticated.** `decode_token` exists but is never called; there is no `get_current_user` dependency, and no route checks organization membership. Every endpoint is public and cross-tenant.
3. **Every route except `/auth/login` is a `pass` stub** (18 of 19). `/auth/login` itself has two bugs that make it crash on the happy path.
4. **Retrieval — the reason the whole pipeline exists — is not implemented**: no similarity query, no vector index, no answer generation, no per-org scoping.
5. **No migrations, no tests, no CI.**

## 1. P0 — Crashes and import errors

### 1.1 `User.hashed_password` mixes `nullable=` with `sa_column=` → import error
- Where: `src/influx/user/domain/models.py:14`
- SQLModel forbids `Field(nullable=True, sa_column=Column(...))`. The whole package fails to import.
- Fix: `hashed_password: bytes | None = Field(default=None, sa_column=Column(LargeBinary, nullable=True))` — or decide it is NOT nullable (see 4.2) and drop `nullable` entirely.

### 1.2 API startup reads `private_key.pem`, which does not exist
- Where: `src/influx/main.py:17`, `src/influx/core/config.py:61`
- `Path(JWT_SECRET_PATH).read_bytes()` in the lifespan → `FileNotFoundError` on boot. Path is relative to CWD, not to the project.
- Fix: load the JWT secret from an env var (`JWT_SECRET`), fail fast with a clear message if missing or shorter than 32 bytes; document it in `.env.example`. (Also see 2.5 on the HS256/"private key" mismatch.)

### 1.3 `/auth/login` does not `await login(...)`
- Where: `src/influx/auth/routes.py:13`
- `login` is `async`; the route passes the coroutine to `JSONResponse(content=...)` → `TypeError: Object of type coroutine is not JSON serializable` (plus a "coroutine was never awaited" warning).
- Fix: `token = await login(...)`.

### 1.4 `login()` calls `.first()` on a coroutine
- Where: `src/influx/auth/application/service.py:13`
- `await session.exec(statement=statement).first()` binds as `await (session.exec(...).first())` → `AttributeError: 'coroutine' object has no attribute 'first'`.
- Fix: `user = (await session.exec(statement)).first()`.

### 1.5 `init-db` seeds a `str` password into a `LargeBinary` column
- Where: `src/influx/__init__.py:110`
- `hashed_password="placeholder"` is a `str`; the column is now `bytes` → asyncpg `DataError` on insert. After 1.1 the seed would also produce a user nobody can log in as.
- Fix: either seed with `encrypt_password("…")` for dev only, or stop seeding users entirely (see 2.13).

### 1.6 `login()` crashes when `hashed_password` is `NULL`
- Where: `src/influx/auth/application/service.py:14`, `password.py:7`
- Column is nullable; `bcrypt.checkpw(pw, None)` → `TypeError` → HTTP 500.
- Fix: `if user is None or user.hashed_password is None or not check_password(...)`. Run a dummy `checkpw` in the negative branch too (see 2.7).

### 1.7 `InvalidCredentialsException` is a bare `Exception` → HTTP 500 on wrong password
- Where: `src/influx/auth/exceptions.py:1`
- Not a `ProblemDetailsException`, so the RFC 9457 handler never sees it; FastAPI returns a plain-text 500.
- Fix: subclass `ProblemDetailsException` with `status = 401`, `type = "tag:influx,2026:invalid-credentials"`, `headers = {"WWW-Authenticate": "Bearer"}`.

### 1.8 `CHUNK_OVERLAP_WORDS` is defined twice with different values
- Where: `src/influx/core/config.py:42` (`30`) and `:44` (`int(getenv(..., "50"))`)
- The second assignment wins, so the effective default is 50, the comment and README say 30. Silent behaviour change in chunking.
- Fix: keep one definition (the env-driven one, already documented in `.env.example` as `50`) and align the comment/README.

### 1.9 `OrganizationDeactivation.requested_at` is a naive `DateTime` with a tz-aware default
- Where: `src/influx/organization/domain/models.py:24`
- Every other model uses the `UtcDateTime` decorator; this one uses SQLModel's default `DateTime` (no tz). asyncpg rejects an aware `datetime` for `timestamp without time zone` (`can't subtract offset-naive and offset-aware datetimes`) → any insert fails.
- Fix: `sa_column=Column(UtcDateTime, nullable=False)` (move `UtcDateTime` to `core/` so both modules can import it).

### 1.11 Deleting an `Organization` will fail (and load every blob into RAM first)
- Where: `src/influx/organization/domain/models.py:35-38`, `crawler/domain/models.py` (`ondelete="CASCADE"` on the FKs)
- The FKs cascade at DB level, but the ORM relationships (`crawls`, `links`, `pages`, `documents`) do not set `passive_deletes=True`. On `session.delete(org)` SQLAlchemy loads all children (including every `Document.blob`) and tries to set `organization_id = NULL` → `IntegrityError` (NOT NULL).
- Fix: `sa_relationship_kwargs={"passive_deletes": True}` on all four; same for `User.administered_organizations` / `participations`. `Participation` FKs have no `ondelete` at all — add `CASCADE`.

### 1.12 Uncommitted working tree contains the broken state
- `git status`: 9 modified + 6 untracked files (`auth/`, `retrieval/`, `main.py`, `core/exceptions.py`, routes). The last commit builds; HEAD + working tree does not.
- Fix: land the fixes above, then commit in coherent pieces (models / auth / routes / exceptions). Don't ship the intermediate state.

## 2. P1 — Security (before anything is reachable from the internet)

### 2.1 No authentication dependency — every endpoint is public
- Where: `src/influx/auth/application/tokens.py:9` (`decode_token` unused), all `routes.py`
- Fix: add `get_current_user(token=Depends(OAuth2PasswordBearer(...)), session, secret)` in `auth/dependencies.py`; decode, load `User`, raise 401 problem on failure. Apply via `dependencies=[Depends(get_current_user)]` on every router except `/auth/login`, `/auth/reset-password`, `/health`.

### 2.2 No authorization / tenant isolation
- Where: every `{id}` route in `organization/routes.py`, `crawler/routes.py`, `user/routes.py`, `retrieval/routes.py`
- Nothing checks that the caller belongs to the organization, has `Role.ADMIN`, or is the user being read/edited. All data is cross-tenant.
- Fix: `require_membership(org_id, role=None)` dependency that joins `Participation`; `require_self_or_admin` for `/users/{id}`; a `superadmin` flag on `User` for `GET /organizations/` (list all) and org creation. Decide whether `Organization.administrator_id` or `Participation.role == ADMIN` is the source of truth (see 4.1) — right now there are two.

### 2.3 Login takes `email` and `password` as **query parameters**
- Where: `src/influx/auth/routes.py:12`
- Plain `str` params on a POST are query params in FastAPI → credentials land in the URL, access logs, proxy logs, browser history.
- Fix: JSON body (`LoginRequest(BaseModel)`) or `OAuth2PasswordRequestForm`. Validate `email` with `EmailStr`, cap password length (see 2.8).

### 2.4 Session cookie is set without any protective attributes
- Where: `src/influx/auth/routes.py:15`
- `set_cookie(key="Authentication", value="Bearer " + token)` — no `httponly`, `secure`, `samesite`, `max_age`, `path`. The token is *also* returned in the body. `"Bearer "` inside a cookie value is non-standard and breaks on cookie parsers that split on spaces.
- Fix: pick one transport. If cookie: `httponly=True, secure=True, samesite="lax", max_age=TTL, path="/api"`, and add CSRF protection for state-changing routes. If header: return `{"access_token": token, "token_type": "bearer"}` and don't set a cookie.

### 2.5 JWT: symmetric HS256 keyed from a file called `private_key.pem`
- Where: `src/influx/core/config.py:60-62`, `auth/application/tokens.py`
- HS256 uses a shared secret, not a private key; the naming will lead someone to drop a real RSA PEM in there and sign with its full text. Claims: `user_id` as a string instead of the standard `sub`; no `iss`/`aud`/`jti`; no refresh token, no logout, no revocation. 30-minute TTL with no refresh means either a bad UX or someone bumps `JWT_TTL_MINUTES` to a week.
- Fix: `JWT_SECRET` env var (≥32 random bytes) **or** switch to `EdDSA`/`RS256` with a real key pair. Use `sub`, add `iss`/`aud`, validate them in `decode_token`. Add refresh tokens (DB-backed, revocable) or at least a short-lived access token + `/auth/logout` that blocklists `jti`.

### 2.6 422 validation responses echo the request `input` — including passwords
- Where: `src/influx/core/exceptions.py:128`
- `exc.errors()` in FastAPI/pydantic v2 includes `input` (and `ctx`, which can hold exception objects). A malformed login request would echo the password back in the problem body.
- Fix: project each error to `{loc, msg, type}` only.

### 2.7 User enumeration via timing at login
- Where: `src/influx/auth/application/service.py:14`
- `check_password` (bcrypt, ~100 ms) runs only when the email exists. Response-time difference reveals which emails are registered.
- Fix: always run `bcrypt.checkpw` against a fixed dummy hash when the user is missing; same generic 401 message either way.

### 2.8 bcrypt 5.x raises on passwords > 72 bytes → HTTP 500
- Where: `src/influx/auth/application/password.py:4,7` (bcrypt 5.0.0 installed)
- bcrypt ≥5 raises `ValueError` for inputs longer than 72 bytes instead of truncating. No password policy exists at all (no min length either).
- Fix: validate `8 ≤ len(password.encode()) ≤ 72` in the request schema; consider `sha256`-prehash if you want to allow longer passphrases. Catch `ValueError` → 400 problem.

### 2.9 No rate limiting or brute-force protection
- Where: `/auth/login`, `/auth/reset-password`, `/crawler/` (expensive), `/retrieval/` (calls Ollama)
- Fix: `slowapi` or a reverse-proxy limit (nginx/Caddy/Traefik) keyed by IP + email for login; per-org quota for crawl and retrieval.

### 2.10 SSRF: the crawler fetches whatever URL it is given
- Where: `src/influx/crawler/application/crawler.py:66` (`run_crawl(organization_id, root_url)`), `crawler/routes.py:8`, `crawler/application/crawler.py:203` (`_download_document`)
- Once `POST /crawler/` is wired, an org admin can point a crawl at `http://localhost:11434` (Ollama), `http://postgres:5432`, `http://169.254.169.254/` (cloud metadata), or any host on your private network; document downloads follow links found in pages. `Organization` has no bound domain, so nothing constrains `root_url` today.
- Fix: (a) `Organization.domain` set by a superadmin, crawl root must be a `Link` under that registrable domain; (b) resolve the host and reject loopback / private / link-local / multicast ranges (`ipaddress`) before every fetch, including redirects and document URLs; (c) allow only `http`/`https`; (d) cap redirects.

### 2.11 ReDoS via user-supplied crawl rules
- Where: `src/influx/crawler/domain/models.py:130` (`CrawlRule.regex`), `organization/routes.py:28` (`add_crawl_rule(regex)`), `crawler/application/service.py:76,96` (`re.compile`, `pattern.search` against every URL)
- Python `re` is backtracking; a pattern like `(a+)+$` from a tenant stalls every worker on every URL of their crawl.
- Fix: length cap (≤200 chars), forbid nested quantifiers or use a linear-time engine (`google-re2`), test-compile on insert and reject `re.error`, and run `is_excluded` with a bounded pattern set per org.

### 2.12 Postgres published on all interfaces with default credentials
- Where: `docker-compose.yml:10` (`"${DB_PORT:-5432}:5432"`), `core/config.py:13-17` (defaults `influx/influx`)
- On a VPS this exposes Postgres to the internet with a known password.
- Fix: `"127.0.0.1:${DB_PORT:-5432}:5432"` or drop the port mapping and put the app in the same compose network; refuse to start when `DB_PASSWORD == "influx"` outside dev; generate a real password in `.env`.

### 2.13 `init-db` seeds a known example user into whatever DB it points at
- Where: `src/influx/__init__.py:9-10,56,93-117`
- `init-db` is documented as *the* setup command and unconditionally creates `mario.rossi@example.com` / organization `Esempio`. In production that is a known account.
- Fix: separate `seed-dev` command guarded by an `INFLUX_ENV=development` check; `init-db` (or the migration step) creates schema only.

### 2.14 No environment distinction, no fail-fast config validation
- Where: `src/influx/core/config.py`
- Nothing says dev vs prod. Missing/weak secrets, default DB password, missing Ollama are discovered at first request.
- `INFLUX_ENV` (`development|production`) now exists in `config.py` (it only switches the log handlers, see `core/logging.py`; the compose `app` service sets `production`). Still missing: validate at import — required secrets present, DB password not default in prod, `JWT_SECRET` length. Keep the flat-constants style; a single `_require(name)` helper is enough.

### 2.15 No CORS, no security headers, `/docs` and `/openapi.json` public
- Where: `src/influx/main.py:24`
- Fix: `CORSMiddleware` with an explicit origin list; `docs_url=None, redoc_url=None, openapi_url=None` in prod (or behind auth); security headers (`HSTS`, `X-Content-Type-Options`, `Referrer-Policy`) at the reverse proxy.

### 2.16 Unhandled exceptions are not problem+json and carry no request id
- Where: `src/influx/core/exceptions.py:131-136`
- No handler for bare `Exception` → Starlette's plain-text 500. Make sure `debug=False` in prod (Starlette's debug page prints locals).
- Fix: catch-all handler returning a 500 problem with `instance` = request path and a generated `request_id` also written to the log; middleware that assigns `X-Request-ID`.

### 2.17 Table models used directly as API I/O would leak `hashed_password`
- Where: no request/response schemas exist anywhere (`*/routes.py`)
- Returning `User` from a route serialises `hashed_password`. `PATCH /users/{id}` with the table model as body would let a caller set `id`, `hashed_password`, `email` of someone else.
- Fix: dedicated `UserRead`, `UserUpdate`, `OrganizationRead`, `CrawlRead`, … Pydantic/SQLModel (non-table) schemas; `response_model=` on every route.

### 2.18 No User-Agent / contact identification on the crawler
- Where: `src/influx/crawler/application/crawler.py:85` (`ImpitHttpClient()` default UA)
- Not strictly security, but sites you crawl will block or report you; identify as `InfluxBot/0.1 (+https://…/bot)`.

### 2.19 Regex file path `--exclude-file` and `LOG_FILE` are relative to CWD
- Where: `core/config.py:46`, `__init__.py:67`
- Minor, but under systemd/Docker the CWD is not the repo → logs go to `/logs/…` or fail. Use absolute paths from env.

### 2.20 `python-dotenv` is used but not a declared dependency
- Where: `core/config.py:5`, `pyproject.toml`
- Comes in transitively via `uvicorn[standard]`; a future `fastapi[standard]` change silently breaks config. Declare it.

### 2.21 `aiosqlite` is still a dependency but SQLite no longer works
- Where: `pyproject.toml:12`, `core/db.py:23` (unconditional `CREATE EXTENSION vector`), `crawler/application/storage.py:27-30` (sqlite insert dialect), `crawler/domain/models.py:21-42` (`UtcDateTime` docstring about SQLite)
- Decide: drop SQLite (remove `aiosqlite`, sqlite dialect branch, docstring) or restore the dialect guard in `init_db`. Half-support is the worst option — pgvector needs Postgres anyway.

### 2.22 Password reset is a no-op that returns 200
- Where: `auth/routes.py:18`, `auth/application/service.py:20`
- Fix (full flow): `POST /auth/reset-password` (email → always 202, generate single-use token with expiry stored hashed in a `PasswordReset` table, send email), `POST /auth/reset-password/confirm` (token + new password). Needs an email sender (SMTP creds in env) — not present at all today.

## 4. Data model

### 4.1 Two sources of "who is admin"
- `Organization.administrator_id` (single FK) **and** `Participation.role == ADMIN`. The seed creates the org with `administrator_id` but no `Participation` row, so "list my orgs via participations" would miss the admin's own org.
- Decide: keep `Participation.role` only (multiple admins, uniform queries) and drop `administrator_id`, or keep `administrator_id` as "owner" and always create an ADMIN participation alongside. Enforce "at least one admin" in the service layer.

### 4.2 `User` is missing basic fields
- `created_at`, `is_active`, `email_verified_at`, `is_superadmin` (needed for 2.2). Email is not normalised (`unique=True` is case-sensitive → `Mario@x.it` and `mario@x.it` are two users). Nullable `hashed_password` — if it is for invited-not-yet-registered users, say so in a comment and handle it in login (1.6); otherwise make it NOT NULL.

### 4.3 `Organization` has no domain
- Crawls take an arbitrary `root_url`; `Link` records subdomains of "the org's domain" but that domain is never stored. Add `domain` (registrable domain, validated with `tldextract`), `created_at`. `active` exists but is never read (login, crawl, retrieval should all refuse an inactive org). `name` is globally unique with `max_length=30` — intentional?

### 4.4 `CrawlRule` is not wired to anything
- `crawler/domain/models.py:130`. The crawler still gets rules from `--exclude`/`--exclude-file` only. No `UniqueConstraint(organization_id, regex)`, no `created_at`, no relationship on `Organization`. `run_crawl` should load `CrawlRule` rows for the org and build `UrlRules` from them (merged with CLI ones).

### 4.5 `Crawl` stores no outcome
- `run_crawl` returns `CrawlResult(requests_finished, requests_failed, pages, documents, links)` and the scheduler throws it away. Add those counters plus `error: str | None`, `requested_by_user_id`, `link_id` (which Link was crawled) so `GET /crawler/{id}` has something to show. `automated` defaults to `True` but the only producer (CLI) passes `False`.

### 4.6 `ContentChunk` cannot be queried per organization efficiently and has no vector index
- No `organization_id` (must join `Page`); no `created_at`. **No HNSW/IVFFlat index** on `embedding` → every retrieval is a sequential scan over all chunks of all tenants. Add `organization_id` (denormalised, FK, indexed) and `CREATE INDEX … USING hnsw (embedding vector_cosine_ops)` — via a migration, not `create_all`.

### 4.7 `Document` blobs live in Postgres and are loaded eagerly
- Up to 64 MB per row (`MAX_DOCUMENT_BYTES`); any `select(Document)` pulls the bytes. No `content_type`, no extracted `text`, no `size`. Options: keep in PG but mark `blob` as `deferred` and add the metadata columns; or move bytes to disk/S3-compatible storage and keep only a key + hash.

### 4.8 `Page` — no `title`, no lifecycle
- `title` is needed for retrieval citations. `last_seen_at` is written but never read: pages that disappeared from the site are never pruned, and their chunks keep answering queries (5.7). `hash` is `nullable` but always set — make it NOT NULL.

### 4.9 `OrganizationDeactivation`
- Naive datetime (1.9). Missing `requested_by_user_id`, `processed_at`/`status`. No route creates it.

### 4.10 No migrations
- `SQLModel.metadata.create_all` at every startup (`core/db.py:24`, called from `main.py:18` and `__init__.py:54`). It never alters existing tables, cannot change PG enum types (`Role`, `CrawlStatus`), and `CREATE EXTENSION` needs superuser on managed Postgres. Every model change above requires one.
- Fix: Alembic (async env), `init-db` → `alembic upgrade head`, remove DDL from the API lifespan. Do this **before** the schema changes in 4.x so they become the first migrations.

### 4.11 Timestamp consistency
- `UtcDateTime` lives in `crawler/domain/models.py`; `organization` and `user` models can't use it without a crawler import (which `organization` already does, creating a cross-module dependency). Move `UtcDateTime` + `_utcnow` to `core/`.

## 5. Business logic gaps

### Crawler

#### 5.1 Scheduler exists only in the CLI process
- `CrawlScheduler` is instantiated in `__init__.py:69`; `main.py` never creates one, so `POST /crawler/` has nothing to submit to. The in-process queue is lost on restart; `Crawl` rows stay `PENDING` forever; `ONGOING` rows from a crashed process are never reconciled.
- Fix (recommended): a separate **worker process** (`influx worker`) that polls the DB for `PENDING` crawls (`SELECT … FOR UPDATE SKIP LOCKED`), runs them, and on startup marks stale `ONGOING` as `FAILED`. The API only inserts `Crawl` rows. Add it as a `worker` service in compose (same image; set `stop_grace_period` above Docker's 10 s default, the SIGTERM path waits for in-flight requests). This also avoids running 10-concurrent-request crawls + HTML parsing on the API event loop, and works with `uvicorn --workers N` (an in-process scheduler would start N copies).

#### 5.2 No crawl limits
- No `max_requests_per_crawl`, max depth, wall-clock cap, or per-org quota (`crawler.py:86-97`). One org can crawl a 2M-page site for days. Add caps in config and per-org overrides.

#### 5.3 Duplicate concurrent crawls
- Nothing prevents two `ONGOING` crawls of the same org/root. Add a guard in `submit` / the worker (one active crawl per `(organization_id, root_url)`).

#### 5.4 `automated` crawls are never scheduled
- The flag exists, no periodic scheduler (cron/APScheduler/worker loop) creates them. Define the policy (per org interval? enabled `Link`s only?) and implement it in the worker (5.1).

#### 5.5 Enabling a `Link` does nothing
- `set_link_status` stub; the intended flow (enable subdomain → it gets crawled) needs the worker to pick up enabled links.

#### 5.6 No cancel
- No way to stop a running crawl from the API; `CrawlInterrupted` is SIGINT-only. Worker should check a `cancel_requested` flag between batches.

#### 5.7 Stale pages/documents are never pruned
- After a re-crawl, URLs that 404 or vanished stay in `page`/`document` (with their chunks) forever. Use `last_seen_at < crawl.started_at` at the end of a successful crawl to delete or mark them.

#### 5.8 Storage flush failure inside `__aexit__` masks the crawl exception
- `storage.py:78`: if `run_crawl` raises *and* the final `flush()` raises, the flush error replaces the original. Minor; log both.

### Ingestion

#### 5.9 Embedding runs only from the CLI and never after a crawl
- `embed_pages` is called only from `__init__.py:77`. Either the worker runs it automatically after a `SUCCEEDED` crawl, or an API trigger exists; otherwise crawled content is never searchable.

#### 5.10 Documents are never parsed or embedded
- README says so; still a functional gap. Needs text extraction per type (`pypdf`/`pdfminer` for PDF, `python-docx`, `odfpy`, something for legacy `.doc`), a `text` column or a `DocumentChunk`/generalised chunk table, and the same hash-based incremental logic as pages.

#### 5.11 Embedding is strictly sequential and has no timeouts
- One page at a time, one Ollama call chain (`page_service.py:48-76`); `AsyncClient(host=OLLAMA_HOST)` created at import with no timeout/retry (`embedding_service.py:15`). A 50k-page site takes many hours; an Ollama hiccup raises out of the whole run. Add bounded concurrency (semaphore), a timeout, and retry on connection errors. Dimension check only inspects `vectors[0]` (`embedding_service.py:30`).

### Retrieval

#### 5.12 No retrieval at all
- `retrieval/routes.py:9` is `pass`. `embed_query` exists; nothing uses it. Needed: `POST /organizations/{id}/query` → `embed_query` → `select(ContentChunk, Page.url, Page.title).join(Page).where(Page.organization_id == id).order_by(ContentChunk.embedding.cosine_distance(vector)).limit(k)` → return chunks with source URLs and scores. Requires the HNSW index (4.6).

#### 5.13 Answer generation is configured but absent
- `OLLAMA_ENRICHMENT_MODEL = "qwen3:8b"` (`config.py:36`) is never used. If the product is RAG (not just search), add the generation step: prompt with top-k chunks, cite URLs, stream the answer, cap context tokens. Guard cost with per-org rate limits (2.9).

#### 5.14 `/retrieval/metrics` has no data behind it
- No `QueryLog` table (org, user, question, top-k ids, latency, feedback). Add it and log every query; metrics become aggregates over it.

### Organization / users

#### 5.15 Deactivation and `active` are not enforced
- `OrganizationDeactivation` rows are never created; `Organization.active` is never checked in login, crawl submission, retrieval.

#### 5.16 Org deletion semantics
- With cascades fixed (1.11), `DELETE /organizations/{id}` erases all crawled data. Decide soft-delete (`active=False` + retention window) vs hard delete, and who may do it.

#### 5.17 User deletion vs administered organizations
- `Organization.administrator_id` has no `ondelete`; deleting a user who administers an org fails. Tie to 4.1.

#### 5.18 No invitation / membership flow
- `Participation` can only be created by SQL today. Needed for any second user.
